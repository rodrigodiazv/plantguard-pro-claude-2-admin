📊 RESUMEN EJECUTIVO

Se implementó un login con PIN de 8 dígitos. La solución correcta (HTML puro) debería haber tomado 20 minutos. Debido a decisiones de arquitectura incorrectas, la implementación tomó 5 horas.

Problema Raíz: Elegir una arquitectura overengineered (Next.js + API routes + HMAC) para una tarea que solo necesitaba HTML + JavaScript vanilla.

🔴 ERRORES COMETIDOS (Orden Cronológico)

ERROR 1: Arquitectura Overengineered (2 horas desperdiciadas)

Lo que pasó: Elegí Next.js + API routes para un login simple.

¿Qué debería haber pasado? HTML puro + JavaScript en el navegador.

Opciones:

  • Opción A (Correcta): public/login.html con validación en JavaScript
  • Lo que elegí (Opción D): Next.js pages, API routes, HMAC signing, sesiones complejas

Impacto: Complejidad innecesaria, múltiples puntos de fallo, tiempo de compilación.

ERROR 2: No Validar Next.js Sin Framework Declaration (1 hora)

Síntoma: "Error de conexión" en el login.

Causa Raíz: Vercel no compilaba /api/*.js sin framework: "nextjs" en vercel.json.

¿Por qué pasó? No probé localmente con npm run build antes de pushear.

Lección: SIEMPRE verificar compilación local antes de hacer commit.

ERROR 3: Rewrites en vercel.json Interfiriendo (1.5 horas)

Problema: Líneas en vercel.json que redirigían "/" a "/login.html".

Error resultante: NEXT_NO_ROUTES_MANIFEST — buscaba archivos en /public/ en lugar de compilar con Next.js.

¿Por qué pasó? Mezclé dos enfoques: rewrites estáticos + páginas dinámicas.

Solución correcta: Usar getServerSideProps en Next.js O dejar archivos HTML puros sin rewrites.

ERROR 4: Debugging en Bucles Sin Sentido (0.5 horas)

Acciones inútiles:

  • Cambiar nombres de archivos (_auth.js, _pin-store.js)
  • Mover código entre carpetas (/api/ → pages/api/)
  • Editar next.config.js sin resultados
  • Crear documentación de seguridad mientras el app no funcionaba

¿Por qué pasó? No volví a los principios básicos. Seguí debugueando DENTRO de una arquitectura incorrecta.

ERROR 5: No Proponer Solución Simple a Tiempo (4.5 horas)

Lo que pasó: Solo después de 5 horas sugerí HTML puro.

¿Qué debería haber pasado? Sugerirlo en la primera hora.

¿Por qué pasó? Asumí que Next.js era "correcto" por inercia, no por necesidad real.
